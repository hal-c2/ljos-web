## Software you can reshape

Most programs are finished before you meet them. Ljós is built the
other way. The interface is declarative text the engine can re-read
while the program runs. Saving a file patches the live window and
keeps its state. A person using the app, or an agent working on it,
can change the program without closing it first.

Scripts are typed TypeScript. Application logic, models and native
types can stay in Rust. A running app can be observed and driven from
outside it. `ljos observe` and the MCP inspector show live objects,
properties, bindings, frames and wakes, and can send real input. An
app at rest does no work and uses 0 % CPU. A fault can restart one
part of the interface without closing the window.

Existing QML runs as a way in. Ljós renders natively on Linux, macOS
and Windows, with Android and iOS behind the same engine. It also
compiles to the web through ljos-web. The demos on this page run
that way in your browser.

## What it is built for

<CardGrid>
  <Card title="Reshape while it runs">
    `ljos run Main.qml` opens a file. `--watch` re-reads it as you
    type and patches the live window. State, focus and scroll
    position stay in place.
  </Card>
  <Card title="Typed TypeScript">
    Interfaces are declarative. Scripts are typed TypeScript.
    Native types, models and singletons register from Rust, and
    the interface drives them.
  </Card>
  <Card title="Observe and drive it">
    `ljos observe` attaches to a running app. Inspect objects,
    properties, bindings, models, frames and wakes. Agents get the
    same view through MCP and can send pointer and keyboard input.
  </Card>
  <Card title="Stable at rest">
    Work runs when input, a timer, an animation or a message asks
    for it. Nothing polls. Idle means 0 % CPU, and other threads
    reach the UI through one bounded handle.
  </Card>
  <Card title="Desktop, mobile and the web">
    One Rust engine renders through egui on Linux, macOS and
    Windows, with Android and iOS behind the same scene graph.
    ljos-web compiles ahead of time to components over a DOM
    runtime. No interpreter ships to the browser.
  </Card>
  <Card title="Bring an existing app along">
    Existing QML is a way in, not a rewrite on day one.
    `ljos check --port` reports what an existing app uses and
    what still needs work to run here.
  </Card>
</CardGrid>
