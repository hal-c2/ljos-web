# The QML examples of the pinned docs that stand on ljos.dev as plain
# code, and why: `<page> <n> <reason> [note…]`, where <page> is the
# page's path under docs/site and <n> counts its `qml` fences from 1,
# as ljos-ui's crates/ljos_cli/tests/docs_site.txt counts them (a
# group by its root, the `qml` fence without `file=`). Read
# by site/scripts/codeblocks-ledger.mjs; both sites' suites fail on a
# plain example missing here and on an entry that runs now, so this
# list only shrinks.
#
# Reasons:
#   host-types      it uses what a Rust program registers (types,
#                   modules, context objects); no page can run it
#   shows-findings  it shows what the checks find, so it is meant not
#                   to compile; ljos-ui lists it so too
#   web:<gap>       it runs in Ljós, not yet on the web; <gap> names
#                   what ljos-web lacks
#   docs:<gap>      it is not whole as the page writes it: ljos check
#                   only warns, and the page should give it what it
#                   reads (ljos-ui's docs to change; until then
#                   site/codeblock-files/<page>/<n>/ may give it)
#   logs            it runs, and says something on the console as it
#                   is made that the page means it to: it stays live,
#                   and the note says what. Anything else a block says
#                   as it is made leaves it plain until it is listed
